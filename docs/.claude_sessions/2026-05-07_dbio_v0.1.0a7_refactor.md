# 2026-05-07 — `biom3.dbio` v0.1.0a7 refactor + docs reorg + CLI renames

## Context

Two pieces of accumulated debt in the `biom3.dbio` subpackage finally
landed on the same day:

1. **Architectural debt.** All 26 dbio files lived in one flat
   directory with inconsistent naming — `swissprot.py` was a reader,
   `expasy.py` was a parser, `taxonomy.py` mixed two distinct classes,
   and `uniprot_client.py` was dead code superseded by the TrEMBL
   annotation cache (built and promoted to the data share the day
   before, 2026-05-06).
2. **Loose docs.** 28+ markdown files at `docs/`, no thematic
   grouping. Setup guides for six clusters mingled with dbio
   references and RL training docs.

The plan (`~/.claude/plans/fuzzy-hatching-dove.md`) called for a
no-shims, hard-break refactor since the user base is small enough to
absorb breaking changes without a deprecation cycle. Three
sequential phases over one day:

1. Tag `v0.1.0a6` as pre-refactor revert point.
2. Subpackage reorganization + `uniprot_client.py` removal +
   doc-content updates → `v0.1.0a7`.
3. Loose-docs reorganization into `setup/ dbio/ reinforcement_learning/`.

A late-stage CLI naming pass folded two long-name renames into the
same v0.1.0a7 breaking-change window so external consumers absorb
them together.

## Phase A — `biom3.dbio` subpackage refactor (`38890ee`, 25 files moved)

Target structure:

```
src/biom3/dbio/
├── __init__.py · __main__.py · config.py · caption.py · stats.py · enrich.py
├── parsers/      swissprot_dat, pfam_stockholm, expasy_dat, smart_tsv, brenda_flatfile
├── readers/      base, swissprot_csv, pfam_csv, taxonomy
├── builders/     source_{swissprot,pfam,trembl,expasy,smart,brenda}, pfam_subsets
├── helpers/      annotation_cache, csv_to_parquet
└── pipelines/    build_dataset
```

Naming principles that emerged:

- **Parsers** named after input format suffix: `_dat`, `_stockholm`,
  `_tsv`, `_flatfile`. Always.
- **Readers** named after input artifact: `_csv` for CSV/Parquet
  readers.
- **Builders** lose `build_` prefix (the directory says "builders").
  `source_` prefix marks primary builders; bare names mark selective
  ones (`pfam_subsets.py`).
- **Helpers** descriptively named (`annotation_cache.py`,
  `csv_to_parquet.py`).
- **Pipelines** keep `build_` because the user-facing CLI is
  `biom3_build_dataset` and matching reduces cognitive load.

Implementation: 19 `git mv` operations (rename history preserved at
98–100% similarity), then a single `xargs sed` pass updating ~50
internal imports across `src/biom3/dbio/`, `tests/dbio_tests/`,
`tests/test_imports.py`, `demos/`, and `scripts/dataset_building/`.
Sed used end-of-word `\b` anchors and longest-pattern-first ordering
to handle substring overlaps (`swissprot` vs `swissprot_dat`,
`pfam` vs `pfam_metadata`).

`__main__.py`'s nine lazy imports updated to the new paths. CLI
entry points in `pyproject.toml` unaffected — they reference
`biom3.dbio.__main__:run_*` and the `__main__` shell didn't move.

## Phase B — `uniprot_client.py` removal (`8b25c08`, 6 files, -430 lines)

The TrEMBL annotation cache (built 2026-05-06, promoted to
`/data/data-share/BioM3-data-share/data/dbio_constructs/`) closed
the last gap that made the UniProt REST API enrichment path useful.
Removed in cascade:

- **`src/biom3/dbio/uniprot_client.py`** — entire file deleted
  (`UniProtClient` + `UniProtCache`).
- **`src/biom3/dbio/enrich.py`** — JSON parser block deleted
  (`parse_protein_name`, `parse_gene_ontology`,
  `parse_subcellular_location`, `extract_annotations`, ~150 lines).
  `enrich_dataframe()` lost its `uniprot_data` parameter; the
  `if uniprot_data:` branch and the `extract_annotations(entry)`
  call inside it both gone.
- **`pipelines/build_dataset.py`** — removed `--uniprot_cache_dir`
  and `--uniprot_batch_size` argparse arguments, the API fallback
  block at priority 3, the `uniprot_data` variable, and the
  `uniprot_data=uniprot_data` kwarg in the `enrich_dataframe` call.
  Replaced API fallback with a `ValueError` that names the supported
  paths:

  > `--enrich_pfam` requires `--annotation_cache` or `--uniprot_dat`.
  > The legacy UniProt REST API path was removed in v0.1.0a7; build
  > a TrEMBL annotation cache via `biom3_build_annotation_cache`
  > instead.

- **`tests/dbio_tests/test_enrich.py`** — `TestExtractAnnotations`
  class removed; `TestEnrichDataframe` converted from
  `uniprot_data=...` to the `local_annotations=...` path (same
  end-state, exercises the live code path).
- **`tests/test_imports.py`** — `import biom3.dbio.uniprot_client`
  dropped; replaced by explicit imports of every new subpackage
  submodule (24 imports).
- **`parsers/swissprot_dat.py`** — module docstring updated to drop
  the "Replaces the UniProt REST API" framing (the API is gone, not
  replaced).

Test count went 247 → 245 (the two deleted tests were the
`TestExtractAnnotations` cases).

## Phase G — CLI renames (`a73c22b`, 11 files)

Two long-name CLIs still carried pre-refactor module names. Folded
into the v0.1.0a7 breaking-change window so external consumers
absorb both breaks together:

- `biom3_build_annotated_pfam_subsets` → `biom3_build_pfam_subsets`
  (matches `builders/pfam_subsets.py`; "annotated" is implied by
  every dbio builder).
- `biom3_convert_to_parquet` → `biom3_csv_to_parquet` (matches
  `helpers/csv_to_parquet.py`; new name names both source and
  destination format).

Dispatch functions in `__main__.py` renamed to match
(`run_build_pfam_subsets`, `run_csv_to_parquet`). Doc and demo
updates in the same commit. `pip install -e .` regenerated
`src/biom3.egg-info/entry_points.txt` cleanly.

## Plan vs. execution deltas

The plan-mode plan at `~/.claude/plans/fuzzy-hatching-dove.md` named
the orchestrator subpackage `pipelines/` over `orchestrators/` for
brevity and the plural-symmetry argument. Kept that decision.

The plan budgeted Phase 2 as "one coordinated PR with ≥ 2 commits";
landed as 5 commits (move/rewrite, removal, test reorg, docs, version
bump) plus the late-stage doc reorganization (Phase F) and CLI
renames (Phase G). The split into more, smaller, semantically-distinct
commits keeps `git bisect` clean and makes the breaking-change
markers (`feat(dbio)!:`, `refactor(dbio)!:`) visible in the log.
